## 1. 개요

주식 스터디 '한탕'(8인)의 종목 추천·매도를 텔레그램 단톡방에서 자동 감지해 구글시트에 기록하고,
평일 07:00 카드뉴스를 단톡방에 발송한다.

**멤버 8인**: 안병열 · 김동환 · 이광훈 · 송지호 · 조형오 · 어정윤 · 이원호 · 김태완

**스터디 규칙**
- 주 1회 라운드(그 주 첫 KRX 거래일) 종목 1개 추천. 라운드일을 넘겨 올리면 지각 = 패널티
- 매수·매도가는 **KRX 정규장 종가**
- 추천 후 한 달(추천일+1개월 전날의 직전 거래일) 자동 매도. 그 안에 1회 종가 매도 가능
- ETF(인버스·레버리지 포함)·해외주식 가능
- 같은 종목 재추천 가능(연속 2회 한도 해석은 미확정, §12)
- **미추천 시 -10% 패널티** 자동 부여. **한국 증시 휴장일엔 패널티 없음**, 다음 거래일 기준 추천
- 분기 대회. 분기 점수는 분기마다 새로 시작. **직전 분기 보유 종목은 새 분기와 무관**(중복 아님)
- 새 분기 시작 후 직전 분기 스코어가 다 집계될 때까지 **두 분기 카드 동시 발송**
- 상금: 1등·2등(26년 2분기부터 20만·10만). 보너스(결혼 +10% 등)는 운영자 지시로 기록

**역대 1·2등(단톡방 공지 기준)**: 25Q3 안병열·송지호 / 25Q4 송지호·김태완 / 26Q1 이광훈·송지호 /
26Q2 어정윤·이광훈 / 26Q3 김동환·안병열(KRX 재계산 후 확정치: 김동환 +72.30%, 안병열 -10.24%).
26Q1 시트는 3월 추천분 매도가가 비어 합계가 깨져 있다 — 결과는 공지로만 확정됨.

### 3-2. STARTUP_OPS — 시트 쓰기·워크플로 실행의 유일한 통로

`telegram_listener_realtime.py`의 `STARTUP_OPS` 목록에 작업을 넣고 push →
`hantang_listener_deploy`가 VM에 배포·재기동 → 기동 직후 목록을 한 번씩 실행.
실행한 id는 VM `_ops_done.txt`에 남아 재기동해도 반복 안 됨(실패한 id는 다음 기동 때 재시도 — 실패 원인을 고치거나 목록에서 빼라).
결과는 운영자 텔레그램으로 간다(작업자는 못 본다 → 확인은 `listener_log` dispatch 또는 시트 읽기).

| op | 하는 일 | 가드 |
|---|---|---|
| `buy` | 활성에 추천 기록(`allow_dup`) | 같은 종목·같은 추천일 있으면 중단 |
| `sell` | 지정 분기 탭에서 1건 매도 | 매칭 정확히 1건 + `expect` 라벨 포함 |
| `sell_rest` | 직전+현재 분기 남은 보유분 전부 매도 | 남은 건수 = `expect_count` |
| `restore` | 실현 행 → 활성 복원(매도 취소) | 종목·추천일·매도일 일치 1건 |
| `resell` | 잘못 판 추천분 복원 + 맞는 추천분을 같은 매도일·같은 실현 행에 매도 | 잘못 판 행 1건, 맞는 보유 1건↑ |
| `bonus` | 실현에 보너스·조정 행 추가(S=100, T=100+pct) | 같은 라벨·날짜 있으면 중단 |
| `fix_realized` | 실현 행 S·T 정정(다건) | 행마다 종목·추천일·매도일·기존 S·T 일치 |
| `dispatch` | 워크플로 실행(VM dispatch PAT) — `daily_report` test_mode, `listener_log` 등 | — |

**재발송 절차**: `dispatch daily_report test_mode=true` → Actions 로그 확인 → `test_mode=false`.
특정 탭 카드만 보내려면 `hantang/ops/card_only.json` `{"date":"YYYY-MM-DD","sheets":["26년 4분기"]}` (`git add -f`).
**리스너 로그 확인**: `dispatch listener_log {"pattern":"...","lines":"..","scan":".."}` → 1~2분 뒤
`/repos/.../actions/workflows/listener_log.yml/runs`의 최신 run 로그 zip을 받아 읽는다.

### 3-3. 시트 읽기

사용자 Chrome(Claude in Chrome, 구글 로그인 상태)에서 시트를 열고 JS로
`fetch('https://docs.google.com/spreadsheets/d/<ID>/export?format=csv&gid=<GID>')`.
**gviz CSV는 쓰지 말 것** — 열 타입 추론 때문에 값이 빠진다. 결과 문자열에 `=`·쿼리스트링 같은 패턴이
많으면 출력이 차단되므로 `/`·`~` 구분자로 출력하고, 길면 `window.__D`에 담아 20줄씩 나눠 읽는다.

Chrome이 꺼져 있으면 시트를 못 읽는다 → `listener_log`로 결과만 확인.

## 7. 데일리 리포트 (`update_gsheets.py`)

평일 07:00 KST. 순서:

1. 현재 분기 탭 확보(없으면 생성), 직전 분기 탭 확인. 직전 분기 `_pending_sell` 잔여 여부를 **먼저** 기록
2. `fix_pending_sells` — 리스너 매도분 매도가를 매도일 종가로 확정
3. `apply_missed_recommendation_penalties(현재 분기)` — **카드보다 먼저**(예전엔 다음 날 카드에야 보였다)
4. `process_quarter(현재)` — 실현 칸 확보 → 기준가·현재가 → 자동매도 → 카드 발송
5. 직전 분기 — 활성 또는 매도가 미확정 건이 남아 있으면 갱신·카드 발송(분기 전환기 카드 2장)

**시세 소스 (원칙 6)**
- 국내: **다음 금융 일봉**(`finance.daum.net/api/quote/A{code}/days`, Referer 필요) = KRX 정규장 종가.
  다음에 없는 종목(ETN 등)은 네이버 일봉에서 **익일 등락폭으로 역산**(종가[t] = 종가[t+1] − 등락[t+1]).
- 네이버 `m.stock.naver.com/api/stock/{code}/price`·`siseJson`의 종가는 **NXT 포함 통합 최종가**다.
  삼성전자 10/19: 네이버 223,500 vs KRX 218,000. 8/14~11/3 기록이 이걸로 오염돼 11/6 40건 정정함.
- 해외: yfinance(정규장 종가, 분할 소급 조정).
- `latest_close`는 마지막으로 마감된 세션. 장중 실행이면 전일 종가가 정상.

**권리락(무상증자·분할)**: `adj_factor(rec, 기준일)` = 추천일과 기준일 사이 권리락 계수의 곱.
계수는 야후 `splits`(1/ratio) + 수동 보정표 `CORP_ACTIONS`. 활성 기준가 L = 추천일 종가 × 계수,
자동매도 시 기준가는 매도일까지의 계수만. 네이버 등락폭으로 추정하는 방식은 NXT 때문에 오탐 → 폐기.
예) 엘앤씨바이오 10/26 무상증자 1:1 → 10/19 추천분 기준가 66,800 × 0.5 = 33,400.
매수가를 절반으로 낮추는 게 맞다(1주가 2주가 된 것과 같은 수익률).

**실현 칸 확보**: `ensure_p_capacity` — 자동매도·패널티에 필요한 만큼 빈 실현 행이 없으면 블록
마지막 행 앞에 행을 끼워 넣는다(소계 SUM 범위가 따라 늘어남). 같은 실행의 다건 자동매도는 `used_p`로 행 중복 배정 방지.

**라운드 판정**: `round_day(d)` = 그 주 첫 KRX 거래일. 패널티는 라운드 **다음 날 아침**(`dd < today`).
라운드는 시트에 그 날짜 추천이 하나라도 있어야 인식된다.

**카드**: 표식 `.card_sent_<날짜>_<탭>`(탭별). `ops/card_only.json` 날짜가 오늘이면 지정 탭만 발송.
건수 표기 `N종목 +M매도 +K기타`(패널티·보너스는 기타, 합계엔 반영).
