## 1. 개요

주식 스터디 '한탕'(8인)의 종목 추천·매도를 텔레그램 단톡방에서 자동 감지해 구글시트에 기록하고,
매일 아침 07:00 카드뉴스를 단톡방에 발송한다.

**멤버 8인**: 안병열 · 김동환 · 이광훈 · 송지호 · 조형오 · 어정윤 · 이원호 · 김태완

**스터디 규칙(시트에 기재된 것)**
- 주 1회(월요일 라운드) 종목 1개 추천
- 한 달 이내 1회 종가 익절/손절 매도 가능, 추가 매수 불가
- ETF(인버스·레버리지 포함)·해외주식 가능하나 되도록 국내 종목
- 같은 종목 2회까지 연속 추천 가능
- **미추천 시 -10% 패널티** (자동 부여)
- 지각은 지각이다. 라운드일을 넘겨 올리면 패널티 (사용자 명시 기준)

## 3. 쓰기 경로와 세션 복구

**구글시트에 쓰는 유일한 경로는 GitHub Actions다.** 시트 자격증명이 리포지토리 시크릿에만 있다.
작업 컨테이너에서 직접 시트를 건드릴 수 없다.

### 컨테이너가 초기화됐을 때 (자주 일어난다)

세션이 갈리면 `/tmp/go` 클론과 PAT가 함께 사라진다. 환경변수 `GH_TOKEN`·`GITHUB_TOKEN`은
이 레포 권한이 없는 다른 토큰이라 401이 난다. 복구 절차:

```bash
# 1. 레포 재클론 (public이라 인증 없이 읽기 가능)
cd /tmp && git clone -q https://github.com/won3ho-max/go.git go

# 2. 세션 트랜스크립트에서 PAT 회수 (과거 turn에 remote URL이 출력됐으면 남아 있다)
#    /root/.claude/projects/-home-claude/<session-id>.jsonl 에서
#    github_pat_[A-Za-z0-9_]{20,} 패턴을 뽑아 각각 검증
curl -s --noproxy '*' -o /dev/null -w "%{http_code}" -H "Authorization: Bearer $T" \
  https://api.github.com/repos/won3ho-max/go/actions/workflows     # 200이면 유효

# 3. 저장 (화면에 출력하지 말 것)
#    /tmp/.ght, chmod 600
```

**프록시를 반드시 우회해야 한다.**

| 작업 | 명령 |
|---|---|
| GitHub API | `curl --noproxy '*' -H "Authorization: Bearer $T" ...` |
| git push | `env -u https_proxy -u http_proxy -u HTTPS_PROXY -u HTTP_PROXY git -c http.proxy= push origin main` |

프록시를 타면 `access denied by the git proxy: ... not in this session's authorized repository set` 403이 난다.

**트랜스크립트에 토큰이 없으면** 사용자에게 (1) 데스크톱 앱에서 레포를 대화 소스로 연결, 또는
(2) `repo`+`workflow` 권한 PAT 신규 발급을 요청한다. 그동안 사용자가 직접 돌릴 수 있도록
워크플로명과 입력값을 표로 정리해 함께 준다.

## 5. 리스너 처리 흐름

```
텔레그램 메시지
  → detect_tag()        #종목추천/#매수/#추천 → buy, #매도/#청산 → sell, 없으면 무시
  → MEMBER_MAP[user_id] # 미매핑이면 알림만
  → resolve_stock()     # §6
  → 매수: find_active_dup() 로 중복 확인 → add_stock()
    매도: active_holdings() 로 후보 좁힘 → sell_stock() (가장 과거 1건)
  → notify_admin() + log()
```

**설계 원칙 — fail-closed.** 종목을 확정하지 못하면 기록하지 않고 알림만 보낸다.
틀린 기록보다 누락이 낫다. 누락은 알림으로 보이지만, 틀린 기록은 조용히 분기 결산까지 간다.

**로그 포맷** — 기록·보류·매도 모두 `근거`와 `원문`을 남긴다(2026-09-28 추가).
예전엔 미인식 건만 원문을 남겨, 엉뚱한 종목이 '정상 기록'되면 되짚을 수가 없었다.

## 6. 종목 인식 (`resolve_stock`) — 가장 손이 많이 간 부분

### 후보 우선순위

| 순위 | 후보 | 비고 |
|---|---|---|
| ① | 보유 종목 대조 | 매도 경로에서만 |
| ② | 원문 거래소표기 티커 | `NASDAQ:XXX` 형태 |
| ③ | LLM 티커 | **현재 죽어 있음 (§10-1)** |
| ④ | LLM 종목명(한/영) | 동일 |
| ⑤ | 원문 괄호 티커 | `(COHR)`·`[BITX]`. **이름 구간에서만** |
| ⑥ | 앞 5줄 토큰 휴리스틱 | 현재 실질적 주력 |
| ⑦ | 본인 과거 추천 라벨 대조 | 위가 전부 실패했을 때만 |

모든 후보는 네이버 자동완성(`ac.stock.naver.com/ac`)으로 검증한다. ⑦만 예외 —
시트에 이미 있는 라벨은 그 자체가 정답 표기다.

### 각 가드의 유래 (풀기 전에 반드시 읽을 것)

| 가드 | 막는 사고 |
|---|---|
| 2패스(완전일치 우선) | 네이버가 `KODEX WTI원유선물` 검색에 **인버스**를 정방향보다 앞에 준다 |
| 부분일치 시 최단명 채택 | 같은 이유 |
| `strict_foreign` | `SKT` ⊂ `SK Telecom Co Ltd ADR` 부분포함으로 미국 ADR이 기록됐다 |
| ADR→국내상장 대체 | 스터디는 국내 상장 기준. `SKM`→`SK텔레콤`으로 치환 |
| 접두 일치 예외 | `트럼프 미디어`→`트럼프 미디어 & 테크놀로지 그룹(DJT)` 축약 표기 인정 |
| 접두 ≥4자 & 정식명의 1/3 이상 | `비트코인`(4자)이 `비트코인 인프라스트럭처 애퀴지션`(15자)에 걸렸다 |
| 절반 길이 가드 | `SOL`→`SOL AI반도체TOP2플러스` 우연 일치 차단 |
| `(H)` 헤지 접미사 보호 | `KODEX WTI원유선물(H)`의 H를 미국 티커 H(Hyatt)로 읽었다 |
| 괄호 티커 = 이름 구간만 | `인쇄회로기판(PCB)`→미국 은행 `PCB 뱅코프`. `비상발전기(UPS)`→택배회사 UPS |
| 토큰 정리 문자셋 | 스마트 따옴표 `“제이에스링크”`, 마침표 `대덕전자.` 가 질의를 깨뜨렸다 |

**"이름 구간"**(`_name_region`)은 앞 3줄에서 사유 시작 표식(`1.`·`-`·`>`·`ㅇ`·`사유`) 앞까지다.
한글 기업설명에서 괄호는 티커보다 **영문 약어 자리**로 훨씬 자주 쓰인다는 관찰에서 나왔다.

## 7. 데일리 리포트 (`update_gsheets.py`)

매일 07:00 KST. 순서:

1. `fix_pending_sells` — 리스너 자동매도분 매도가를 매도일 종가로 확정
2. `process_quarter(현재 분기)` — 기준가 채우기 → 현재가 갱신 → 자동매도 → **카드 생성·발송**
3. `apply_missed_recommendation_penalties` — 라운드별 미추천 -10%
4. 직전 분기 — 활성 종목 또는 `_pending_sell` 미확정 건이 남아 있는 동안 갱신·**카드도 별도 발송**(분기 전환기엔 카드 2장). 카드 중복 방지 표식은 `.card_sent_<날짜>_<탭>`

**시세 소스**: 국내는 네이버(`m.stock.naver.com/api/stock/{code}/price`), 해외는 yfinance.
야후가 하루~이틀 밀리는 사고가 세 번 나서 국내는 네이버로 바꿨다.
`latest_close`는 **마지막으로 마감된 세션**을 쓴다. 장중에 돌리면 전일 종가가 나오는 게 정상이다.

**라운드 판정**: `round_day(d)` = 그 주의 첫 KRX 거래일. 월요일로 못박았다가
2026-08-17(대체공휴일)에 라운드가 통째로 누락됐다.

**패널티 적용 시점**: `dd < today`인 라운드만. 즉 라운드 **다음 날 아침**에 부여된다.

**카드 건수 표기**: `N종목 +M매도 +K기타`. 패널티·보너스는 매도가 아니므로 '기타'로 분리한다.
단, 총 수익률 합계에는 패널티가 그대로 들어간다(점수 반영).

## 8. 워크플로

| 워크플로 | 용도 | 주요 입력 |
|---|---|---|
| `daily_report` | 데일리 수동 실행 | `test_mode`(true면 개인 텔레로) |
| `batch_add` | 기록/교정/삭제/보너스 | `stocks` `rename` `remove` `rm_penalty` `refix` `bonus` `rec_date` `dry_run` `allow_dup` |
| `manual_sell` | 수동 매도 | `person` `stock` `sell_date` `sell_price` `dry_run` |
| `sheet_dump` | 시트 읽기 전용 덤프 | `sheet`(예: `26년 3분기`) |
| `listener_log` | 리스너 로그 조회 | `pattern` `lines` `scan` |
| `resolve_test` | 종목 인식만 시험 | `text` `holdings` `history` |
| `listener_diag` | 리스너 환경 진단 | 없음 |
| `send_admin` | 운영자 텔레그램 발송 | `text` |
| `install_daily_timer` | VM 크론 설치/제거 | `action` |
| `hantang_listener_deploy` | 리스너 배포 | push 시 자동 |

`stocks`·`remove` 등은 **쉼표 구분**이다. 줄바꿈(`\n`)은 구분자가 아니다 — 한 덩어리로 들어가 사고가 난다.

## 10. 알려진 함정·사고 이력

**10-1. Anthropic 크레딧 소진 (2026-08-09~, 미해결)**
LLM 1차 인식 경로가 죽어 있다. 휴리스틱 단독으로 버티는 중이라 표기 변주마다 새 구멍이 난다.
인식 실패가 무더기로 나면 1순위 의심. `listener_diag`로 확인.
사용자는 충전을 원치 않는다(추산 월 $0.03 수준으로 안내했음).

**10-2. 구글시트 5xx**
`open_by_key`·`ws.cell()` 같은 호출이 재시도 밖에 있어 메시지·데일리가 통째로 유실됐다.
현재는 리스너·데일리 모두 `sheet_retry`로 감쌌고, 데일리는 워크플로가 3·6분 간격으로 최대 3회 재실행한다.
카드 중복 발송은 `.card_sent_<날짜>` 표식으로 막는다.

**10-3. GitHub Actions cron 지연**
최대 3시간까지 밀린다(07:00 예정 → 10:30 시작 관측). 그래서 VM 크론으로 옮겼다.
`daily_report.yml`에 schedule을 되살리지 말 것.

**10-4. 분당 읽기 쿼터(429)**
패널티 루프가 멤버마다 시트를 통째로 다시 읽어 라운드가 쌓이자 터졌다. 한 번만 읽고 로컬에 반영한다.

**10-5. `sheet_dump`의 '3분기'는 25년·26년 양쪽에 걸린다**
`26년 3분기`처럼 연도를 붙여라.

**10-6. 재추천 보류**
같은 종목을 이미 활성으로 들고 있으면 자동기록하지 않고 보류한다(fail-safe).
정당한 재추천이면 `allow_dup=true`로 수동 추가. 최근 빈도가 높아 `#재추천` 태그 자동 통과를 제안했으나 미채택.

**10-7. 인식 실패가 패널티로 바뀌는 구조 (미해결)**
리스너가 종목을 못 잡으면 시트에 기록이 없고, 다음 날 아침 데일리가 그걸 '미추천'으로 보고 -10%를 부여한다.
2026-09-28 어정윤 건이 실제 사례(수동 삭제함). **미인식 알림이 뜬 멤버는 그 라운드 패널티를 보류하도록
바꾸는 안을 사용자에게 제안해 둔 상태.**

**10-8. 익명 발신(GroupAnonymousBot)**
`1087968824`는 익명 전송된 이원호다. MEMBER_MAP에 둘 다 매핑돼 있다.

**10-9. 분기 전환 (2026-10-05 패치)**
- 리스너는 분기별 탭 캐시를 쓴다. 예전엔 기동 시 고른 탭을 재시작 전까지 붙잡았다.
- 매수는 추천일(아래 보정 후)의 분기 탭에 기록. 매도는 직전 분기+현재 분기 보유분을 함께 보고 **직전 분기부터** 판다(리스너·`manual_sell` 공통).
- `batch_add`의 대상 탭은 `rec_date`의 분기. 3분기 정정은 `rec_date`를 3분기 날짜로 줘야 3분기 탭에 쓴다. 기본 `rec_date`는 '그 주 첫 거래일'.
- 휴장일(주말·공휴일)에 올린 추천은 추천일을 **다음 거래일**로 기록. 리스너는 `KRX_HOLIDAYS` 표(2027-10까지)로 판정 — 매년 갱신 필요.

**10-10. 액션 실행 권한 (2026-10-05)**
`deploy_token.txt`의 PAT는 push는 되지만 workflow_dispatch가 403(`Resource not accessible by personal access token`).
이 상태에선 test_mode·sheet_dump·listener_log를 원격에서 못 돌린다. Actions(Read/write) 권한 재부여 필요.

## 12. 미결 과제

1. **Anthropic 크레딧** — 사용자 판단 대기. LLM 경로 복구 시 §10-1 해소.
2. **미인식 → 패널티 자동 부여 차단** — 제안만 해둔 상태(§10-7).
3. **`#재추천` 태그 자동 통과** — 제안만 해둔 상태(§10-6).
4. **매도 '전량' 처리** — 같은 종목 복수 보유 시 매도 메시지 1건이 1건만 처리한다.
   원문에 '전량'이 있으면 전부 매도하는 안을 제안했으나 미채택.
5. **2분기 미결 3건** — 순위표 어정윤·조형오 누락, 송지호 효성티앤씨 시트값, 김동환 카르만홀딩스 하루 밀림.
6. **같은 종목 연속 추천 한도 해석** — 규칙 5번("2회까지 연속")이 '분기 내 총 2회'인지
   '연속 2회'인지 스터디에서 확정되지 않았다. 조형오 SOL 조선TOP3플러스레버리지가 분기 4회째.
